SUMMARY:
The build is clean and the gate is real: `bunx tsc --noEmit` exits 0, `bun test src` runs 121 tests across 15 files in 190ms with 0 failures, `bun run lint` reports 61 warnings and 0 errors, and .github/workflows/ci.yml runs typecheck, test, lint and build on every pull request. The problem is what those numbers cover. The Balasaur Score is computed twice, once in src/lib/score.ts and once as the `rating_balasaur` generated column added in supabase/migrations/20260811100000_balasaur_score_v2_tmdb.sql, and the two disagree on 191 of 67,667 scored titles. Postgres `round()` on a double precision value rounds ties to the nearest even number (`round(72.5::double precision)` is 72, `round(73.5::double precision)` is 74) while JavaScript `Math.round` always rounds a tie up, so the same title gets two different numbers. Running the shipped `computeBalasaurScore` on the live row for Guardians of the Galaxy Vol. 3 returns 77 while the database column holds 76; Predator is 69 versus 68, One Flew Over the Cuckoo's Nest 87 versus 86. Both values reach the screen: src/lib/media.server.ts:1773 and src/lib/catalog.functions.ts:114 build the badge from the TypeScript function, while src/lib/media.server.ts:2124 overwrites it with the database value for the "more like this" rail, under a comment reading "The DB-generated score is canonical when present." Coverage is measured over 1,779 lines of the 28,238 in src/, and the three files carrying the most logic (media.server.ts at 2,569 lines, catalog.functions.ts at 759, night.ts at 326) have no tests at all.

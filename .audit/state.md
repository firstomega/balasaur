SCORE_AGREE: yes

SUMMARY:
The guest-to-account handoff is the best-built part of this area and it works: sign in with picks made while signed out and they are batch upserted, invalid values coerced first so one corrupt row cannot sink the batch, and localStorage is cleared only after the write returns without an error (src/hooks/useUserStatus.ts lines 196 to 209). Failed writes fall back to delete-then-insert and then to a local outbox that is merged back into the list on the next load, so a pick does not vanish on a flaky network. What drags the score down is everything around that one path. Two things are outright broken: the region picker on title pages reads localStorage inside a useState initializer (src/components/balasaur/WhereToWatch.tsx line 104), so a returning visitor who once switched to GB gets a server-rendered US provider list and a client first render of GB, which is a hydration mismatch on a page Google renders; and the cookie banner reads and writes storage with no try/catch (src/lib/consent.ts lines 47, 77, 83) while every other storage helper in the repo guards, so a visitor with site data blocked throws inside an effect that runs on every page. The guest library is one JSON blob under one key, written with the whole map each time, so two guest tabs are last-writer-wins on the entire list. Scale check against production: 109 rows in user_media_status across 2 users, both of them the owner's, and 13 Movie Night rooms. None of this is costing traffic today, and none of it is on the path to indexation or AdSense, which is why 5.5 rather than lower is right.

STRENGTHS:
- The sign-up handoff does not lie. The migration checks the returned error before clearing local data and leaves the local copy plus the retry flag in place when the write fails (useUserStatus.ts lines 202 to 209). The comment says this replaced a version that destroyed picks while showing a success message.
- Bad local data cannot poison the batch. Status, sentiment and intent are validated against the same vocabularies the database CHECK constraints enforce and coerced or dropped before upsert (lines 106 to 141), and entries with a non-finite timestamp are skipped. The unique constraint the upsert targets does exist in production: 2 unique or primary constraints on user_media_status.
- Every write has three levels of retreat: upsert, then manual delete plus insert if the conflict target is missing, then the local outbox, which the next load merges back into the visible list (lines 312 to 331, 230 to 233).
- Movie Night avoids the exact hydration trap that WhereToWatch falls into. The room token is read after mount behind a tokenRead flag, with a comment saying the earlier version flashed "You are invited" at people already in the room (src/routes/night.$code.tsx lines 66 to 83). The daily game and the filter rail do the same.
- Signing out cannot leak the previous account's list, because migration empties localStorage and the anonymous path re-reads from it.

GAPS:
- Hydration mismatch on title pages. WhereToWatch picks its region from localStorage during the first render (line 104), so the server sends one country's provider list and the browser immediately draws another. Title pages are the pages that need to render identically for a crawler.
- Storage blocked takes the whole page down. src/lib/consent.ts touches localStorage outside any try/catch at lines 47, 77 and 83; the banner calls it from an effect that mounts on every route, and the root has an errorComponent, so a visitor with site data disabled can get the error screen instead of the page.
- Two guest tabs lose picks. The whole status map is one localStorage key rewritten in full on every change (useUserStatus.ts lines 42 to 48, 279). The cross-tab listener only refreshes on the storage event; a tab that writes from a stale map overwrites the other tab's entries.
- Signed in, tabs never reconcile. The storage listener exists only on the anonymous branch (lines 168 to 177). A second signed-in tab shows the list as it was when that tab loaded, with no refetch on focus and no realtime, unlike the Movie Night room which does poll on focus every 12 seconds.
- The migration ignores which copy is newer. It upserts with ignoreDuplicates true and then deletes the local copy, so if the account already has a row for a title, a newer edit made while signed out is dropped without a trace. Timestamps are carried in the row but never compared.
- The confirmation only appears in one place. justMigrated is consumed solely by LibraryDeck (src/components/balasaur/LibraryDeck.tsx line 111), so signing in from a title page migrates silently while signing in from the deck says "Saved your N picks".
- No test covers any of this. src/lib/userStatus.test.ts is 49 lines of pure record-shape assertions; the hook, the migration, the outbox and the quota-exceeded path have no test at all. consent.test.ts is the only test that stubs storage, and it stubs a version that never throws.

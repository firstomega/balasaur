SUMMARY:
The hard parts are done well and the easy parts are not. `bun run build` finishes in 8.07s and produces a 656 KB entry chunk (196 KB gzipped) that every visitor downloads; a source-map breakdown of it shows the full Supabase umbrella inside, including storage-js and realtime-js, and `grep -rn "\.storage\." src/` returns zero call sites, so roughly 100 KB of that chunk is code the site never calls. Ten routes opt into `cacheSsrResponse` (src/lib/seo.ts:140, six-hour s-maxage plus stale-while-revalidate), but the homepage is not one of them, and it cannot be: its loader awaits a per-visitor country lookup (src/routes/index.tsx:75) before anything else, which is exactly the "loader output must be identical for every visitor" rule CLAUDE.md sets. So the single most-crawled URL is the one page that pays a fresh 400ms geo wait plus a 1,500ms catalog wait on every request. Against that, the fundamentals are genuinely good: I measured CLS of 0.000 at 390px on /night, /methodology and /about, with zero images missing width/height and no horizontal overflow, and `catalog_facets()` measured 741ms warm via EXPLAIN ANALYZE today, which the loader correctly refuses to await.

STRENGTHS:
- `ssrBudget` (src/lib/ssrBudget.ts) never rejects and always resolves, so no slow or dead backend can stop the HTML from streaming. This is the right shape, and the comments record the July 2 incident that produced it.
- The expensive query is deliberately not awaited. `catalog_facets()` measured 741ms warm in EXPLAIN ANALYZE against production (162,163 buffers touched), and the code comment records 2,673ms cold. The filter rail fills its counts after mount instead. That one decision is what moved the homepage from 1.6 to 1.8 seconds down to the 400ms plus 1,500ms budget it has now.
- Image handling is complete and it shows in measurement: MediaCard.tsx:228-246 has an aspect-[2/3] box, srcSet, sizes, explicit width 342 and height 513, lazy versus eager split, and fetchPriority on the eager one. Measured CLS was 0.000 on all three pages I rendered at 390px, and zero images lacked dimensions.
- Fonts are self-hosted in styles.css and preloaded from __root.tsx:151-165, with a preconnect to image.tmdb.org warming the poster CDN. No render-blocking Google Fonts stylesheet, no font swap shift.
- Build output sets `cache-control: public, max-age=31536000, immutable` on /assets/*, and cache TTLs are tuned per route rather than copy-pasted: play.tsx uses 3600 seconds with a 300-second stale window so the daily puzzle cannot be served past midnight.

GAPS:
- The homepage has no CDN cache. Every request runs the loader fresh: up to 400ms of geo detection, then up to 1,500ms of catalog prefetch, serially, for 1.9 seconds worst case. Ten other routes get six-hour caching. This is the URL Googlebot hits most and it is the only one paying full price, because country-based row ordering made the response per-visitor.
- The entry chunk ships a dead storage client. `@supabase/storage-js` contributes about 101 KB of pre-minification source to index-B7jc4XIk.js and has zero call sites in src/. `@supabase/realtime-js` plus phoenix add roughly 141 KB more and are used in exactly one place, src/lib/night.ts:281, for the Movie Night room that 12 of 13 rooms never completed.
- First load on the homepage is about 292 KB gzipped before a single row of data arrives: 196 KB entry, 30 KB second index chunk, 24 KB TopBar, 24 KB ScoreBadge, 18 KB CSS. For a search visitor arriving on a movie page to read one score, most of that is never exercised.
- No optimistic UI on any Movie Night write. The `write` helper at night.$code.tsx:164-176 awaits the RPC, then awaits a full room refetch, so every "Pick this" tap costs two serial round trips before anything on screen changes. The only feedback is `disabled={busy}` and a "One moment" label.
- The room polls every 12 seconds forever while the tab is open (night.$code.tsx:136), on top of an existing realtime channel that already pokes on change. The comment calls it a fallback, but it runs unconditionally, so a room of four people generates 20 room-state reads per minute whether or not anything happened.
- The sitemap routes carry no cache header. sitemap-titles.xml queries the full 62,000-title set and is refetched from scratch on every crawler hit, which is the one request type guaranteed to be frequent on a site with no human traffic.

METHOD:
